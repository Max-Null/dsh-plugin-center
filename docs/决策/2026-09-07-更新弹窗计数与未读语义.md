# 插件中心：更新弹窗计数与未读语义、UTC 日期节拍（2026-09-07）

> 用户反馈（SSiD 安装版）：启动更新弹窗显示「1 个待升级插件」，插件中心点「检查更新」却
> 有 6 个可更新。排查 + 修复 + SSiD dev L2 验证记录。涉及
> `max-null-plugins/dsh-plugin-center`（0.2.18 → 0.2.19）。

## 一、根因（不是检测不一致，是「未读数」vs「可更新总数」语义错位）

- 弹窗数据流：`checkWhatNew()`（client/index.tsx）→ `rpc('checkUpdates')`（全量可更新列表）
  → `readCache = rpc('readVersions')`（host 已读表
  `~/.dsh/plugin-center-read-versions.json`）→ 弹窗列表 = **`fresh`（未读项）**：
  `digests.filter(d => readCache[d.name] !== d.toVersion)`。
- 用户场景：已读表里 22 个插件版本标记，**唯一未读 = chat-rail 0.6.0 → 0.6.1**（发布当天）
  → 弹窗显示「1」；插件中心「检查更新」列全部 6+（本次实测 7）。数字是**两种口径**。
- 定级：**语义设计缺陷**（弹窗只弹未读是 2026-08-27 的防重复设计，但计数/列表展示未
  表达「还有 N 个已读可更新」），用户感知为 bug。

## 二、修复（client/index.tsx，0.2.19）

1. **弹窗展示全量**：`whatsNewDigests = digests`（当 fresh>0 且今日未弹时）；
   触发条件保持「有未读」——已读的不再重复打扰（防每天弹同一列表）。
2. **已读态呈现**：已读项 `.pc-wn-read`（opacity .55）+「已读」标签；未读默认高亮。
3. **计数语义**：子标题改为「{n} 个有新版本，其中 {m} 个未读」（n=全量、m=未读），
   与插件中心数字一致。
4. **连带修复 UTC 日期坑**：`wnToday()` 原用 `toISOString().slice(0,10)`（UTC）——本地
   每日 00:00-08:00（UTC 仍前一天）会把「昨天已弹」误判成「今天已弹」，晨间弹窗被抑制
   （实测：本地 9/7 00:34 = UTC 9/6，daily 标记 9/6 挡住弹窗）。改为本地日期拼接。

## 四、changelog「介绍」缺失（用户追问「介绍呢？」——GitHub 限流 + 弹窗无降级）

- 现象：弹窗里 7 个插件**没有更新说明**（changelog 列表为空）。
- 根因两层：
  1. **GitHub commits API 匿名限流**（60 次/时/IP）——实测 `403 API rate limit exceeded`，
     `fetchCommitChangelog` 全部返回 []（UA 匿名、无 token）。
  2. **弹窗无降级展示**：插件中心 UpdatesView 有「changelog 拉空保留上次内容」逻辑
     （client 模块级缓存），**WhatsNewDialog 没有**——直接拿 rpc 新结果（空）渲染为空。
- 修复（并入 0.2.19）：
  1. **host 侧 changelog 缓存**（`~/.dsh/plugin-center-changelog-cache.json`，24h TTL、
     200 条上限）：commits 成功时写缓存；拉空/限流时回退**同目标版本**缓存（跨会话/跨重启）。
  2. **readme 预览级**：npm registry 元数据（一次请求同取 `time[version]` 与 readme）——
     readme 取正文前 3 个非空行（跳过 `#`/徽章/HTML/链接 模板行，行截 100 字符），
     末尾附「vX 发布于 D」。**不依赖 GitHub**，介绍信息量 ≥ 占位。
  3. **「GitHub 变更 ↗」外链**：弹窗/更新列表每项（有 github 仓库时）追加仓库外链，
     用户可自行查看 commits/releases（外链不依赖 API）。
  4. **UI 空态占位**：三级都取不到时显示「暂无变更说明（GitHub 限流或仓库无记录，
     稍后自动重试）」——不再整片空白。
- **降级链（最终）**：GitHub commits → 24h 缓存 → **readme 预览** → 发布时间单行 → 占位。
- L2（SSiD dev）：限流期弹窗 7 项显示 readme 预览 + 发布行（函数级验证 dsh-context
  0.44.0 输出 3 行描述 + 发布行）；占位与已读态验证通过。host 侧（缓存/readme）随重启生效，
  用户重启后的新实例已实测发布时间行 ✓（此后为 readme 预览，信息量更高）。
