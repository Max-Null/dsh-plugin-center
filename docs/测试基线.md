# SSiD 全家桶测试基线(v1.0,2026-08-29)

面向 SSiD 全家桶(seek-soul-in-darkness 生态插件 + shell)的统一测试约定。
**目标:任何"改一版点一版"的流程都必须替换为「先测试后交付」。**

## 1. 基建标准(每个仓库)

| 项 | 约定 |
|---|---|
| 运行器 | **vitest**(`pnpm add -D vitest`) |
| 配置 | `vitest.config.ts`(`include: ['tests/**/*.test.ts']`,环境 node) |
| 脚本 | `package.json.scripts.test = "vitest run"` |
| 目录 | `tests/<module>.test.ts`(与 src 同名的纯逻辑测试) |

## 2. 必须覆盖的分层(按优先级)

### L1 纯函数(必测,成本最低)
- 来源/版本判定(`sourceOf`、`compareVersions`、`satisfies`)
- 路径/名称拼装(`tarballNameOf`、`llmLogPath`)
- 状态机判定(`decideLlmState` / `decideLlmRestore`——收敛路径各分支)
- 解析类(`parseLlmLogLine`、release-notes 解析等)

### L2 文件 IO(必测,临时目录)
- 追加/逆序读取(JSONL),含:坏行跳过、文件缺失、非法 status 兜底
- 所有测试写临时目录(`mkdtempSync(tmpdir())`),**绝不触碰真实 profile**

### L3 状态变化(状态机/内存逻辑)
- 用纯函数抽离判定逻辑(参考 `client/llm-decision.ts`):判定零依赖,
  副作用(轮询/toast)放调用方——这是"测得到"的关键手法

### L4 端到端(人工,发版前)
- LLM 更新:采集→确认→会话→执行→回传→轮询收敛(dev 环境)
- 两处入口(插件中心/更新弹窗)+ 批量/单插件会话隔离

## 4. 新增基线后大家遵守的硬规矩

1. **修改 host/client 行为 → 先补/改 L1-L3 用例,再提交**(reference: tsc + vitest 全绿)
2. 任何"人工真机验证发现状态 bug"都要**倒逼一个纯函数回归用例**(如本次 llm-decision 的 ended 收敛)
3. `pnpm test` 全绿是 PR 门禁;typecheck/build 是提交前最低要求

## 5. 本次落地的样板(dsh-plugin-center)

| 文件 | 覆盖 |
|---|---|
| `tests/update.test.ts` | sourceOf 全分支(含 tarball/vendor 顺序回归)、dependencySpecifierOf、buildLlmPrompt、tarballNameOf |
| `tests/llm-log.test.ts` | JSONL 追加/逆序最新/坏行/缺失/非法 status/路径 |
| `tests/llm-decision.test.ts` | 轮询收敛状态机全路径(含"会话停→ended"回归) |

> 实测收益:写测试时立刻暴露 `sourceOf` 的 tarball 分支被 vendor 分支截胡的**真 bug**(已修复)。
